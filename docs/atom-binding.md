# ATOM ADR-0010 B1 binding

`rngd_pd.swap.atom_binding.AtomBinding` is an in-process, persistent owner.
Its B1 operations are `describe(artifact)`, `resident()` and
`plan(switch_plan)`. Planning validates `onggi.switchplan.v1` through
`parse_onggi_switchplan` and always returns `onggi.updateplan.v1`, `mode:
reload`, a reason, the full target byte estimate and `units: []`. Neither
planning nor describing loads a device or changes its identity. `apply` and
`rollback` explicitly raise `NotImplementedError`.

The worker owns transport and device allocation. It calls
`load(artifact, manifest)` after onggi verifies the artifact; only successful
runtime creation admits the supplied `sha256:<64 lowercase hex>` identity.
Repeated `load` calls validate and hash the replacement before closing the old
runtime, then create the replacement with no overlap on the device. Factory
failure after teardown leaves empty residency. Experimental `attach` remains
exclusive and requires closing any current owner first. `close()` clears identity even if native teardown
raises, retaining the engine reference for another cleanup attempt. A closed
public session or experimental engine reports empty residency.

## Artifact metadata

The publisher provides `profile.json`, the coordinate from its compiler run:

```json
{"schema":"onggi.profile.v1","device":"RBLN-CA22","runtime":"rebel","format":"rbln","batch":1}
```

The binding returns that document, preserving additive fields. It does not
derive a coordinate from `.rbln` bytes. The publisher also provides
`atom-binding.json`:

```json
{"graph":"session.rbln","checkpoint":"checkpoint"}
```

`session.rbln` is already compiled. Its publisher sidecar
`session.rbln.json`, generated by `swap.atom.build_session`, supplies positive
`layers` and nonempty `variants`, for example:

```json
{"layers":32,"variants":["B1-S64"]}
```

Paths must be relative, with no parent traversal, drive prefix or absolute
path. Graph, sidecar, metadata and profile resolve inside the artifact;
symlinks escaping it are refused. The checkpoint also resolves inside the
artifact unless the worker supplies already loaded `tables`. Checkpoint
files may be staged as hardlinks; an outside checkpoint symlink is refused.

```python
from rngd_pd.swap.atom_binding import AtomBinding

owner = AtomBinding(device=0, tables=existing_host_tables)  # tables optional
owner.load(verified_artifact, verified_manifest)
owner.resident()
owner.plan(decoded_switchplan)
owner.graph_evidence()
with owner.request() as engine:  # holds the owner lock through native inference
    engine.generate(prompts, n_new)
owner.close()
```

The default factory `load_atom_session(artifact, *, device=0, tables=None)`
calls the existing `AtomSession` with the compiled graph and `Tables` host
embedding inputs. Its native calls are `rebel.RBLNCompiledModel(path)` and
`compiled.create_runtime(device=..., tensor_type="np")`; neither compilation
nor constant refresh is reachable. With `tables`, host checkpoint inputs
are reused too. The compiled object and native runtime remain retained by
the session until close. The binding does not decode the vendor binary.

`graph_evidence()` returns `{graph, sha256, runtime_api}`. SHA-256 is a
streamed digest of the compiled source file at admission, suitable for
comparing source reuse. It is neither device readback nor a hash of all
checkpoint inputs. `runtime_api` is `public-AtomSession`, `injected-factory`
or `experimental-constant-weight-free-abi`. Immutable artifacts and correct
manifest verification are the caller's responsibility.

## Experimental retained constant engine

`attach(artifact, manifest, engine)` transfers ownership of an already
prepared `ConstantWeightDecode`: its active variant must have retained
runtime and compiled entries. The binding never calls `prepare`, `swap` or
`apply_delta`; the owning worker must establish engine/artifact provenance
before attaching. Attachment does not reconstruct a constant engine from a
saved graph and does not establish public-API conformance for that path.

The existing #28 engine has the following experimental dependencies. These
are dependencies of preparing or operating that engine, not of the default
public B1 loader:

| Dependency | Existing use |
| --- | --- |
| `rebel.compile_context.CompileContext` | Eager global weight-sharing context, `is_eager_mode`, `use_global_ctx`, `device_id` |
| `compile_from_torch(..., _intmd_mode="gen")` | Internal compilation mode in `prepare` |
| `rebel.core.weight_free.apply_weight_free_weights` | Binds CPU parameter identities to the compiled constant pools |
| `runtime._runtime_handle` | Private native-handle access |
| `extern_transform_key_groups()` | Enumerates transform inputs and checks emitted metadata |
| `get_host_op_keys()` | Finds host parameter dependencies |
| `reset_applied_transform_graphs()` | Clears native transform application bookkeeping |
| `apply_extern_transforms(...)` | Writes complete transform dependency groups |
| `apply_host_params(...)` | Rebinds host parameter pointers, requiring retained CPU owners |
| `RBLN_WEIGHT_FREE=1`, rebel `0.11.0` | Version-specific process initialization and ABI guard |

The binding's attachment checks repo-owned `active`, `graphs`, `compiled`
and `_closed` state. Its ordinary session liveness check reads repo-owned
`AtomSession.rt`. These are Python ownership checks, not additional vendor
native APIs. The public factory does not import `atom_constants` or touch
the vendor-private handle. `atom_bundles` is imported by the existing
`atom` module, but its Optimum loader is never invoked by this binding.

The #28 experimental engine retains its global context and original CPU
parameter objects; ordinary saved graphs lack the meta-load mapping needed
to restore it. B1 public native evidence must use the ordinary precompiled
`AtomSession` path and must not relabel experimental attachment as public.

## Verification and size

CPU tests exercise publisher metadata, strict manifests, failed admission,
wrong-base refusal, deterministic pure reload plans, traversal rejection,
retained-engine admission and liveness, source SHA stability, and public
loading with a compile function that raises if called. They inject the
vendor boundary and do not demonstrate native residency.

`request()` holds the owner lock for an entire inference request; concurrent
load and close calls wait until it exits, including when inference raises.
The `engine` property is a read-only compatibility view for inspection;
serving calls must use `request()` to preserve draining.

Run the focused checks with `PYTHONPATH=src python -m pytest
tests/swap/test_atom_binding.py tests/swap/test_atom.py
tests/swap/test_onggi_switchplan.py -q`. Full B1 kit execution requires the
worker's persistent transport and real device loading; the kit's synthetic
artifacts alone are not native ATOM graphs. A conformance-load hook must
attach or load an actual precompiled native graph in that worker.

The implementation's physical line counts (including comments and blanks)
are reported with the validation results.
It adds no dependency, SDK patch, binary decoder or simulated device mirror.
